# 手机 Gal 一键汉化

在电脑上把 Kirikiri 游戏的日文剧本整本译成简体中文，写回游戏封包，再拿到手机上用 [Tyranor Next](https://github.com/Weiss-UltimateSavior/Tyranor-Next) 游玩。

这个仓库是汉化组件。它不修改 Tyranor Next 的代码，也不随 Tyranor 一起安装。

这是一个半完成品，目前仅支持 Kirikiri 引擎的汉化，其他的引擎还没制作。

测试仅一次，代码由ai完成，主要自用。

测试大体上没问题，但存在部分句子维持日文输出以及部分人名翻译错误的问题，有空再修。

## 设计思路

翻译在电脑上做完，手机只打开已经写好的游戏。

组件和启动器分开。它不使用 `com.tyranor.runtime.` 开头的包名，也不声明 `com.tyranor.runtime.action.LAUNCH`。识别游戏目录时沿用 Tyranor Next 的标记：目录里有 `.xp3` 或 `startup.tjs`。所选文件夹本身没有标记、且只有一个子目录有标记时，那个子目录就是游戏根目录。两个子目录都有标记时判定为无法识别。程序不根据目录深浅或散落的明文猜测引擎。

流程是先抽出全部句子，分批译完，再由使用者确认写回。确认之前，游戏文件保持原样。写回时先把要改的封包复制到所选文件夹旁边的 `{文件夹名}-backup`，用临时文件替换，然后校验。校验失败会从备份恢复。恢复失败则留下备份，并禁止再次写入。

可以分享的是句子包 `.galpack.json`，不是改过的游戏，也不是模型权重。对齐只看 `sourceHash`：原文做 Unicode NFC 正规化后，取 UTF-8 的 SHA-256。同一句原文在游戏里出现多次，导入一次就会全部填上。行号和位置不参与匹配。

导入时：

- 引擎不一致，不写入。
- 汉化包对不上任何一句，不改游戏。
- 已经译过的句子默认不覆盖。
- 没对上的句子保持日文。

当前版本只注册一个引擎插件。引擎是 Kirikiri2，`engineId` 为 `kirikiri`，抽取版本为 `1`。

任务状态从识别、抽取、待翻译、翻译中、待写回、写回、校验走到完成。翻译中可以暂停，再继续。识别失败、抽取失败和校验失败进入失败状态，失败、完成、取消都不能再转移。

成人向台词按普通句子翻译，走同一条流水线。程序不处理任何涉及未成年人的性内容。

手机上的本地翻译模型和应用安装包不在这个仓库里。

## 技术选型

| 部分 | 选择 |
| --- | --- |
| 语言 | Python 3.12。窗口用 tkinter，不另装图形库 |
| 游戏格式 | Kirikiri2 的 XP3 封包和 KAG 脚本（`.ks`） |
| 翻译模型 | `Galtransl-v4-4B-2601-Q5_K_S.gguf`，约 2.82 GB |
| 推理程序 | llama.cpp 的 Windows 版 `llama-server` |
| 句子包 | JSON，`format` 为 1 |

模型文件来自 [GalTransl-v4-4B-2601](https://huggingface.co/SakuraLLM/GalTransl-v4-4B-2601)。上下文 2048，temperature 0.3，top_p 0.8。有 NVIDIA 显卡时下载 CUDA 12.4 版引擎，并附带对应的 CUDA 运行库；否则用 Vulkan，再否则用 CPU。翻译服务地址是 `http://127.0.0.1:8080`。

脚本抽取只读取 `.ks`。对话是一行日文。角色名来自 `@name chara="..."`。方括号控制符留在句子里，译文必须保留同样数量的控制符。代码行、宏和函数不当作台词。

翻译按 8 句一组进行。模型返回的行数必须和这一组相同。出现空行、控制符数量变化，或整段不足 15 字且以拒绝用语开头的回复时，自动再试一次。第二次仍不合格，这一组全部保持日文，不会把少掉的行写到后面的句子上。脚本最后不足 8 句时，按实际句数检查。

写回只改含有译文的封包。译文能用 cp932 保存时仍用 cp932。出现 cp932 无法表示的汉字时，整份脚本改为带 BOM 的 UTF-16 LE，Kirikiri2 可以读取。译文里的真换行不会写进脚本。加密的 XP3 条目会跳过。

下载的引擎和模型放在项目目录的 `runtime`，不放进 git，也不放在 C 盘的用户目录里。

## 使用教程

需要 Windows 和 Python 3.12。引擎加模型大约要 4 GB 磁盘。有 NVIDIA 显卡时翻译更快。

### 在电脑上翻译

1. 双击仓库根目录的 `启动汉化.bat`。
2. 点「选择」，选到含有 `data.xp3` 的游戏文件夹。外层文件夹里只有一个这样的子目录时，也可以选外层。
3. 点「一键准备并翻译」。第一次会下载翻译引擎和模型。窗口会显示进度。中途中断后，再次点击会接着翻译。
4. 完成后，汉化包在 `游戏文件夹\汉化导入\翻译结果.galpack.json`。

### 写回游戏

1. 把要使用的 `.galpack.json` 放在游戏文件夹的 `汉化导入` 里。自己刚译完的包已经在这个位置。
2. 游戏文件夹仍选刚才那一层。
3. 点「一键导入」。这一下会修改游戏，并在旁边生成 `{文件夹名}-backup`。写完前不要关窗口。
4. 没通过检查的句子，以及汉化包里没有的句子，保持日文。

### 在手机上玩

1. 手机系统为 Android 8 或更高，并且是 64 位 ARM。
2. 安装 Tyranor Next。安装包：

   https://github.com/Weiss-UltimateSavior/Tyranor-Next/releases/download/beta-1.65/app-release.apk

3. 手机里已经有同一版本的日文游戏时，只把电脑上写好的 `data.xp3` 覆盖到手机游戏目录里的同名文件。不要拷贝以 `-backup` 结尾的文件夹。
4. 打开 Tyranor Next，添加含有 `data.xp3` 的文件夹。如果仍显示日文，删掉这条游戏记录后再添加一次。

## 目录

```text
启动汉化.bat          打开窗口
galpretrans/galcore   识别、抽取、翻译、句子包和写回
galpretrans/galui     一键窗口和下载
galpretrans/galpc     电脑命令行
galpretrans/galphone  导入和写回命令行
galpretrans/tests     规则测试
runtime/              本机下载的引擎和模型，不进入 git
```

命令行在 `galpretrans` 目录下执行：

```text
python -m galpc extract --root 游戏文件夹
python -m unittest
```

## 当前范围

第一版只做 Kirikiri。这个仓库不包含手机上的本地翻译程序。
